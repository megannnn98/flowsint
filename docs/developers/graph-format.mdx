## Обзор

Визуализация графа во Flowsint построена на двух основных структурах данных: **GraphNode** (представляет сущности) и **GraphEdge** (представляет связи между сущностями). Эти типы определены в `flowsint-app/src/types/graph.ts` и используются во всём фронтенде для отрисовки, взаимодействия и управления данными.

Понимать эти структуры важно, когда вы:
- Создаёте обогатители, которые добавляют узлы и связи
- Работаете над визуализацией во фронтенде
- Отлаживаете проблемы отрисовки графа
- Расширяете граф новыми визуальными возможностями

## GraphNode

`GraphNode` представляет одну сущность в графе (например, домен, IP-адрес, человека). Каждый узел, созданный методом `create_node()` обогатителя, во фронтенде становится `GraphNode`.

```typescript
type GraphNode = {
  id: string
  nodeType: string
  nodeLabel: string
  nodeProperties: NodeProperties
  nodeSize: number
  nodeColor: string | null
  nodeIcon: keyof typeof LucideIcons | null
  nodeImage: string | null
  nodeFlag: flagColor | null
  nodeShape: NodeShape | null
  nodeMetadata: NodeMetadata
  x: number
  y: number
  val?: number
  neighbors?: any[]
  links?: any[]
}
```

### Справочник полей

| Поле | Тип | Описание |
|-------|------|-------------|
| `id` | `string` | Уникальный идентификатор узла. Берётся из значения основного поля типа. |
| `nodeType` | `string` | Тип сущности (например, `"Domain"`, `"Ip"`, `"Email"`). Соответствует имени класса типа Pydantic. |
| `nodeLabel` | `string` | Понятная человеку метка, отображаемая на узле. Задаётся методом `compute_label()` типа. |
| `nodeProperties` | `NodeProperties` | Все свойства сущности в виде пар «ключ — значение». Содержит сериализованные поля типа Pydantic. |
| `nodeSize` | `number` | Визуальный размер узла на графе. |
| `nodeColor` | `string \| null` | Пользовательский цвет узла (CSS-строка цвета) или `null` для значения по умолчанию. |
| `nodeIcon` | `keyof LucideIcons \| null` | Значок на узле из [набора Lucide](https://lucide.dev/icons/) или `null` для значения по умолчанию. |
| `nodeImage` | `string \| null` | URL изображения для отображения на узле (например, фото профиля) или `null`. |
| `nodeFlag` | `flagColor \| null` | Цветной флаг для визуальной пометки (см. «Цвета флагов» ниже) или `null`. |
| `nodeShape` | `NodeShape \| null` | Форма узла (см. «Формы узлов» ниже) или `null` для круга по умолчанию. |
| `nodeMetadata` | `NodeMetadata` | Дополнительные метаданные в виде пар «ключ — значение». Используются для внутреннего учёта и расширенных возможностей. |
| `x` | `number` | Координата X на холсте графа. |
| `y` | `number` | Координата Y на холсте графа. |
| `val` | `number` (необязательно) | Значение, которое движок силовой раскладки использует для расчёта размеров. |
| `neighbors` | `any[]` (необязательно) | Соседние узлы; заполняются движком графа во время работы. |
| `links` | `any[]` (необязательно) | Связанные рёбра; заполняются движком графа во время работы. |

### NodeProperties

```typescript
type NodeProperties = {
  [key: string]: any
}
```

Гибкий объект «ключ — значение», содержащий все свойства сущности. Когда тип Pydantic сериализуется в узел, его поля становятся записями в `nodeProperties`. Например, у узла `Domain` будут `nodeProperties.domain`, `nodeProperties.root` и т. д.

### NodeMetadata

```typescript
type NodeMetadata = {
  [key: string]: any
}
```

Похож на `nodeProperties`, но предназначен для системных метаданных, а не для данных сущности. Здесь могут быть, например, время создания, обогатитель-источник или другие служебные данные.

### Формы узлов

Узлы могут отображаться в одной из четырёх форм:

```typescript
type NodeShape = 'circle' | 'square' | 'hexagon' | 'triangle'
```

| Форма | Назначение |
|-------|----------|
| `circle` | Форма по умолчанию для большинства типов сущностей |
| `square` | Часто используется для сущностей инфраструктуры |
| `hexagon` | Используется для сгруппированных или агрегированных сущностей |
| `triangle` | Используется для сущностей, связанных с тревогами и предупреждениями |

### Цвета флагов

Флаги — система визуальных пометок для узлов. Пользователи могут помечать узлы флагами, чтобы выделять их в ходе расследования.

```typescript
type flagColor = 'red' | 'orange' | 'blue' | 'green' | 'yellow'
```

Каждому цвету флага соответствуют определённые классы Tailwind CSS для единообразного оформления:

| Флаг | Стиль |
|------|-------|
| `red` | `text-red-400 fill-red-200` |
| `orange` | `text-orange-400 fill-orange-200` |
| `blue` | `text-blue-400 fill-blue-200` |
| `green` | `text-green-400 fill-green-200` |
| `yellow` | `text-yellow-400 fill-yellow-200` |

## GraphEdge

`GraphEdge` представляет связь между двумя узлами (например, "RESOLVES_TO", "HAS_SUBDOMAIN", "FOUND_IN_BREACH"). Каждая связь, созданная методом `create_relationship()` обогатителя, во фронтенде становится `GraphEdge`.

```typescript
type GraphEdge = {
  source: GraphNode['id']
  target: GraphNode['id']
  date?: string
  id: string
  label: string
  caption?: string
  type?: string
  weight?: number
  confidence_level?: number | string
}
```

### Справочник полей

| Поле | Тип | Описание |
|-------|------|-------------|
| `source` | `string` | ID исходного узла (узла «from» в связи). |
| `target` | `string` | ID целевого узла (узла «to» в связи). |
| `id` | `string` | Уникальный идентификатор этого ребра. |
| `label` | `string` | Отображаемая метка ребра (например, `"RESOLVES_TO"`, `"HAS_EMAIL"`). Это строка типа связи, переданная в `create_relationship()`. |
| `date` | `string` (необязательно) | Время, связанное со связью (формат ISO 8601). |
| `caption` | `string` (необязательно) | Дополнительный поясняющий текст на ребре или рядом с ним. |
| `type` | `string` (необязательно) | Тип классификации связи для фильтрации или оформления. |
| `weight` | `number` (необязательно) | Числовой вес связи; может использоваться для толщины линии или ранжирования по важности. |
| `confidence_level` | `number \| string` (необязательно) | Оценка достоверности связи — насколько надёжна эта связь. |

## Как обогатители отображаются на граф

Когда вы пишете обогатитель и вызываете методы графа в `postprocess()`, данные проходят такой путь:

### Создание узлов

```python
# В методе postprocess вашего обогатителя
self.create_node(domain)  # domain — объект Pydantic Domain
```

Сервис графа автоматически:
1. Извлекает **имя типа** из класса Pydantic (например, `"Domain"`) -> `nodeType`
2. Читает значение **основного поля** (например, `domain.domain`) -> используется для `id`
3. Читает поле **nodeLabel** (задаётся `compute_label()`) -> `nodeLabel`
4. Сериализует все поля в `nodeProperties`
5. Задаёт значения по умолчанию для визуальных свойств (`nodeSize`, `nodeColor` и т. д.)

### Создание связей

```python
# В методе postprocess вашего обогатителя
self.create_relationship(domain, ip, "RESOLVES_TO")
```

Сервис графа автоматически:
1. Определяет **исходный узел** по типу и основному полю `domain` -> `source`
2. Определяет **целевой узел** по типу и основному полю `ip` -> `target`
3. Использует метку связи `"RESOLVES_TO"` -> `label`
4. Генерирует уникальный `id` для ребра

### Соглашения об именовании связей

Метки связей подчиняются таким соглашениям:
- Используйте **UPPER_SNAKE_CASE** (например, `"RESOLVES_TO"`, `"HAS_SUBDOMAIN"`)
- Используйте **глагольные обороты**, описывающие направление связи (источник -> цель)
- Если метка не указана, по умолчанию используется `"IS_RELATED_TO"`
- Типовые шаблоны:
  - `HAS_*` для владения и вхождения (например, `"HAS_EMAIL"`, `"HAS_SUBDOMAIN"`)
  - `RESOLVES_TO` для DNS-запросов
  - `FOUND_IN_*` для связей с утечками
  - `REGISTERED_BY` для данных WHOIS

## Настройки графа

Визуализация графа настраивается через типы настроек:

### ForceGraphSetting

Управляет физической симуляцией силовой раскладки графа:

```typescript
type ForceGraphSetting = {
  value: any
  min?: number
  max?: number
  step?: number
  type?: string
  description?: string
}
```

### ExtendedSetting

Универсальные настройки с более подробной информацией о типе:

```typescript
type ExtendedSetting = {
  value: any
  type: string
  min?: number
  max?: number
  step?: number
  options?: { value: string; label: string }[]
  description?: string
}
```

Эти настройки позволяют пользователям менять поведение графа: отталкивание узлов, длину связей, скорость симуляции и визуальные предпочтения.

## Зарезервированные свойства

При создании узлов некоторые имена свойств зарезервированы системой, и их нельзя использовать как имена полей в ваших собственных типах:

- `id` — идентификатор узла
- `x`, `y` — координаты позиции
- `nodeLabel` — отображаемая метка (задаётся `compute_label()`)
- `label` — устаревшее поле метки
- `nodeType`, `type` — идентификаторы типа сущности
- `nodeImage`, `nodeIcon`, `nodeColor`, `nodeSize` — визуальные свойства
- `created_at` — время создания
- `sketch_id` — привязка к скетчу расследования

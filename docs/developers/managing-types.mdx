## Как устроена система типов

Система типов Flowsint построена на моделях Pydantic и находится в пакете `flowsint-types`. Каждый тип — это Python-класс, наследующийся от `FlowsintType`, который, в свою очередь, наследуется от `pydantic.BaseModel`, **и должен быть помечен декоратором `@flowsint_type`**, чтобы зарегистрироваться в глобальном реестре типов. Это даёт автоматическую валидацию, сериализацию, генерацию JSON-схем, автообнаружение и специфичные для графа возможности, например автоматическое формирование меток. Архитектура намеренно проста, с минимальной иерархией наследования: каждый тип наследуется от FlowsintType и определяет собственные поля и поведение.

Структура пакета проста. В `flowsint-types/src/flowsint_types/` лежат отдельные Python-файлы для каждого типа. Большинство типов имеют собственный файл, хотя тесно связанные типы иногда делят один файл. Например, в `wallet.py` находятся `CryptoWallet`, `CryptoWalletTransaction` и `CryptoNFT`, потому что они работают как единое смысловое целое.

Сейчас во Flowsint 39 встроенных типов: от сетевых сущностей (домены, IP) до сведений о личности (физические лица, организации), данных безопасности (учётные данные, утечки) и финансовой информации (банковские счета, криптокошельки).

### Что такое FlowsintType?

`FlowsintType` — базовый класс для всех типов сущностей Flowsint. Он расширяет `BaseModel` из Pydantic дополнительной функциональностью, специфичной для графовой базы данных и интерфейса Flowsint:

```python
class FlowsintType(BaseModel):
    """Base class for all Flowsint entity types with nodeLabel support.
    nodeLabel is optional but computed at definition time.

    All classes that inherit from FlowsintType must be decorated with @flowsint_type
    to be registered in the global TYPE_REGISTRY and accessed by their class name.

    Usage:
        from flowsint_types.registry import flowsint_type

        @flowsint_type
        class Domain(FlowsintType):
            domain: str
    """

    nodeLabel: Optional[str] = Field(
        None,
        description="UI-readable label for this entity, the one used on the graph.",
        title="Label",
    )

    # Allow extra keys to support additional properties from user
    class ConfigDict:
        extra = "allow"
```

Поле `nodeLabel` автоматически задаётся типами с помощью декоратора `@model_validator`; именно эта метка отображается на узлах графа в базе Neo4j и в интерфейсе. Каждый тип должен вычислять собственную осмысленную метку на основе своих полей.

`ConfigDict` с `extra = "allow"` означает, что типы принимают дополнительные свойства сверх заданных полей — это удобно для метаданных, передаваемых пользователем.

### Декоратор `@flowsint_type`

Каждый тип **обязан** быть помечен декоратором `@flowsint_type` из `flowsint_types.registry`. Этот декоратор регистрирует тип в глобальном `TYPE_REGISTRY`, что обеспечивает:

- Автообнаружение всех типов при запуске через `load_all_types()`
- Поиск по имени класса (например, `TYPE_REGISTRY.get("Domain")`)
- Поиск по имени в нижнем регистре (например, `TYPE_REGISTRY.get_lowercase("domain")`) для сопоставления с Neo4j

```python
from flowsint_types.registry import flowsint_type
from .flowsint_base import FlowsintType

@flowsint_type  # Required for registration
class MyType(FlowsintType):
    ...
```

Без этого декоратора система не сможет обнаружить ваш тип.

## Создание нового типа

Пройдём весь путь создания нового типа с нуля. В качестве примера возьмём гипотетический тип `Vehicle`.

### Создание файла

Начните с создания нового Python-файла в каталоге типов. Имя файла должно быть в нижнем регистре и совпадать с именем типа в snake_case. Для типа `Vehicle` создайте `vehicle.py`:

```bash
cd flowsint-types/src/flowsint_types/
touch vehicle.py
```

### Базовая структура

Все типы следуют одному структурному шаблону. Вот как выглядит базовый тип:

```python
from pydantic import Field, model_validator
from typing import Optional, Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type

@flowsint_type
class Vehicle(FlowsintType):
    """Represents a vehicle with identifying information."""

    license_plate: str = Field(
        ...,
        description="Vehicle license plate number",
        title="License Plate",
        json_schema_extra={"primary": True},
    )
    brand: Optional[str] = Field(
        None,
        description="Vehicle manufacturer such as Toyota or Ford",
        title="Make"
    )
    model: Optional[str] = Field(
        None,
        description="Vehicle model name",
        title="Model"
    )
    year: Optional[int] = Field(
        None,
        description="Year of manufacture",
        title="Year"
    )

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute a human-readable label for this vehicle."""
        if self.brand and self.model and self.year:
            self.nodeLabel = f"{self.license_plate} ({self.brand} {self.model} {self.year})"
        else:
            self.nodeLabel = self.license_plate
        return self
```

Разберём ключевые компоненты:

**Наследование, импорты и декоратор:**
- Класс наследуется от `FlowsintType`
- Импортируйте `FlowsintType` из `.flowsint_base`
- Импортируйте `flowsint_type` из `.registry` и примените его как декоратор
- Импортируйте `model_validator` и `Self` из Pydantic для вычисления метки

**Docstring:**
- Каждый тип начинается с понятного docstring, объясняющего, что он представляет

**Определение полей:**
- Каждое поле определяется как атрибут класса с подсказками типов
- Используйте функцию Pydantic `Field()`, чтобы задать метаданные
- Обязательные поля используют многоточие (`...`) в качестве значения по умолчанию
- Необязательные поля используют `Optional[Type]` в подсказке типа и `None` как значение по умолчанию
- Всегда указывайте `description` (для документации API) и `title` (для подписей в интерфейсе)

**Основное поле:**
- `json_schema_extra={"primary": True}` помечает уникальный идентификатор этого типа
- Это поле используется как ключ при создании узлов Neo4j
- **Важно:** у каждого типа должно быть ровно одно основное поле
- Выберите поле, которое однозначно идентифицирует экземпляры этого типа

**Вычисление метки:**
- Декоратор `@model_validator(mode='after')` выполняется после всей валидации полей
- Метод должен называться `compute_label` и возвращать `self`
- Он задаёт `self.nodeLabel` — понятную человеку строку, которая появится в интерфейсе и на графе
- Учитывайте случаи, когда необязательные поля могут быть `None`, чтобы не получать уродливые метки
- Метка должна помогать пользователям быстро понять, что это за сущность

### Соглашения об именовании

Flowsint придерживается строгих соглашений об именовании для единообразия кодовой базы. Имена классов используют PascalCase (например, `Vehicle`, `SocialAccount` или `CryptoWallet`). Имена полей используют snake_case (например, `license_plate`, `phone_number` или `email_address`). Это соответствует стандартным соглашениям Python и делает код читаемее.

### Основные поля и метки

Для каждого типа Flowsint критичны две концепции: **основное поле** и **nodeLabel**. Их понимание поможет создавать типы, которые безупречно работают с графовой базой данных и интерфейсом.

**Почему это важно:**
- При создании узлов Neo4j это поле используется как ключ в операциях `MERGE`
- Оно гарантирует однозначную идентификацию каждой сущности в графе
- Сервис графа извлекает это поле, чтобы определить уникальность узла

**Правила для основных полей:**
- У каждого типа должно быть ровно одно основное поле
- Основное поле должно однозначно идентифицировать экземпляры
- Обычно это обязательное поле (с `...` по умолчанию)
- Типичный выбор: идентификаторы, имена пользователей, email, номерные знаки, доменные имена

**Примеры удачных основных полей:**
- `Domain`: поле `domain` (например, "example.com")
- `Email`: поле `email` (например, "user@example.com")
- `Username`: поле `value` (например, "john_doe")
- `Ip`: поле `address` (например, "192.168.1.1")
- `SocialAccount`: поле `id` (вычисляется как "username@platform")

#### Поле nodeLabel и compute_label

`nodeLabel` — это то, что пользователи видят в интерфейсе и на узлах графа. Метка должна быть понятной и помогать быстро понять, что представляет сущность.

**Как это работает:**
1. `FlowsintType` предоставляет поле `nodeLabel` (`Optional[str]`)
2. Ваш тип определяет метод `compute_label`, который задаёт это поле
3. Метод выполняется автоматически после валидации благодаря `@model_validator(mode='after')`

**Базовый шаблон:**

```python
from pydantic import model_validator
from typing import Self

@model_validator(mode='after')
def compute_label(self) -> Self:
    """Compute a human-readable label."""
    self.nodeLabel = f"@{self.value}"
    return self
```

**Продвинутые шаблоны:**

Если есть необязательные поля, корректно обрабатывайте значения `None`:

```python
@model_validator(mode='after')
def compute_label(self) -> Self:
    """Compute label with optional display name."""
    if self.display_name:
        self.nodeLabel = f"{self.display_name} (@{self.username.value})"
    else:
        self.nodeLabel = f"@{self.username.value}"
    return self
```

Для типов с несколькими идентификаторами можно вычислять составной ID:

```python
@model_validator(mode='after')
def compute_label_and_id(self) -> Self:
    """Compute both ID and label."""
    # Compute unique ID from username and platform
    if self.username and self.platform:
        self.id = f"{self.username.value}@{self.platform}"
    elif self.username:
        self.id = self.username.value

    # Compute display label
    if self.display_name:
        self.nodeLabel = f"{self.display_name} (@{self.username.value})"
    else:
        self.nodeLabel = f"@{self.username.value}"
    return self
```

**Лучшие практики для меток:**
- Делайте метки краткими, но информативными
- Сначала указывайте самую идентифицирующую информацию
- Обрабатывайте значения `None` для необязательных полей
- Используйте скобки или разделители для структурирования сложных меток
- Думайте о том, что пользователям нужно видеть на графе с первого взгляда

**Примеры из практики**

```python
# Simple: just the value
# Username: "@john_doe"
self.nodeLabel = f"@{self.value}"

# With context: show platform if available
# Username: "@john_doe (twitter)"
if self.platform:
    self.nodeLabel = f"@{self.value} ({self.platform})"
else:
    self.nodeLabel = f"@{self.value}"

# Rich: combine multiple fields
# Individual: "John Doe (john@example.com)"
if self.email:
    self.nodeLabel = f"{self.full_name} ({self.email})"
else:
    self.nodeLabel = self.full_name

# Complex: show key information
# Breach: "LinkedIn (2021) - 700M records"
self.nodeLabel = f"{self.title} ({self.breachdate.split('-')[0]}) - {self.pwncount:,} records"
```

### Работа с разными типами полей

Pydantic поддерживает широкий набор типов полей помимо простых строк и целых чисел. Вот наиболее частые:

```python
from pydantic import Field, HttpUrl, model_validator
from typing import Optional, List, Dict, Any, Self
from datetime import datetime
from .flowsint_base import FlowsintType
from .registry import flowsint_type

@flowsint_type
class ExampleType(FlowsintType):
    """Demonstrates various field types."""

    # Primary identifier
    id: str = Field(
        ...,
        description="Unique identifier",
        title="ID",
        json_schema_extra={"primary": True}
    )

    # Primitive types
    text_field: str = Field(..., description="A text string", title="Text")
    number_field: int = Field(..., description="An integer number", title="Number")
    decimal_field: float = Field(..., description="A decimal number", title="Decimal")
    boolean_field: bool = Field(..., description="True or false value", title="Boolean")

    # Optional fields
    optional_text: Optional[str] = Field(None, description="Optional text", title="Optional Text")

    # Collections - note the use of default_factory
    tags: List[str] = Field(
        default_factory=list,
        description="List of tag strings",
        title="Tags"
    )

    metadata: Dict[str, Any] = Field(
        default_factory=dict,
        description="Arbitrary metadata dictionary",
        title="Metadata"
    )

    # Special Pydantic types
    website: HttpUrl = Field(..., description="A validated URL", title="Website")
    timestamp: datetime = Field(..., description="Date and time", title="Timestamp")

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this example."""
        self.nodeLabel = f"{self.id} - {self.text_field}"
        return self
```

При работе с изменяемыми типами, такими как списки и словари, всегда используйте `default_factory`, а не задавайте значение по умолчанию напрямую. `default_factory=list` — правильно, а `default=[]` приведёт к тому, что все экземпляры будут делить один и тот же список, что вызывает неочевидные ошибки.

### Добавление валидации

Иногда нужна более сложная валидация, чем простая проверка типов. Pydantic позволяет добавлять собственные валидаторы с помощью декоратора `field_validator`:

```python
from pydantic import Field, field_validator
from typing import Optional, Any, Self
import ipaddress
from .flowsint_base import FlowsintType
from .registry import flowsint_type

@flowsint_type
class Ip(FlowsintType):
    """Represents an IP address with geolocation and ISP information."""

    address: str = Field(
        ...,
        description="IP address",
        title="IP Address",
        json_schema_extra={"primary": True},
    )
   ...
    @field_validator("address")
    @classmethod
    def validate_ip_address(cls, v: str) -> str:
        """Validate that the address is a valid IP address."""
        try:
            ipaddress.ip_address(v)
            return v
        except ValueError:
            raise ValueError(f"Invalid IP address: {v}")
```

Валидаторы получают значение поля и могут либо вернуть (возможно, изменённое) значение, либо выбросить `ValueError` с сообщением об ошибке. Обратите внимание: `@field_validator` выполняется раньше `@model_validator`, поэтому поле проверяется и нормализуется до вычисления метки.

### Ссылки на другие типы

Типам часто нужно ссылаться на другие типы Flowsint. Их можно импортировать и использовать как любой другой Python-тип:

```python
from pydantic import Field, model_validator
from typing import Optional, Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type
from .email import Email
from .phone import Phone

@flowsint_type
class Contact(FlowsintType):
    """Represents contact information for a person."""

    name: str = Field(
        ...,
        description="Contact name",
        title="Name",
        json_schema_extra={"primary": True}
    )
    email: Optional[Email] = Field(None, description="Email address", title="Email")
    phone: Optional[Phone] = Field(None, description="Phone number", title="Phone")

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this contact."""
        self.nodeLabel = self.name
        return self
```

Для типов с циклическими ссылками или сложными отношениями может понадобиться вызвать `model_rebuild()` в конце файла:

```python
from pydantic import Field, model_validator
from typing import Optional, Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type

@flowsint_type
class CryptoWallet(FlowsintType):
    """Represents a cryptocurrency wallet."""

    address: str = Field(
        ...,
        description="Wallet address",
        title="Address",
        json_schema_extra={"primary": True}
    )

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this wallet."""
        self.nodeLabel = self.address
        return self

@flowsint_type
class CryptoWalletTransaction(FlowsintType):
    """Represents a transaction between wallets."""

    transaction_id: str = Field(
        ...,
        description="Unique transaction ID",
        title="Transaction ID",
        json_schema_extra={"primary": True}
    )
    source: CryptoWallet = Field(..., description="Source wallet", title="Source")
    target: Optional[CryptoWallet] = Field(None, description="Target wallet", title="Target")
    amount: float = Field(..., description="Transaction amount", title="Amount")

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this transaction."""
        self.nodeLabel = f"{self.amount} ({self.transaction_id[:8]}...)"
        return self

# Rebuild models to resolve forward references
CryptoWallet.model_rebuild()
CryptoWalletTransaction.model_rebuild()
```

## Экспорт типа

Когда тип создан, декоратор `@flowsint_type` сам выполняет регистрацию. Однако тип также нужно экспортировать из пакета для удобных импортов.

### Обновление экспортов пакета

Откройте `flowsint-types/src/flowsint_types/__init__.py` и добавьте две вещи. Сначала импортируйте новый тип в начале файла вместе с остальными импортами:

```python
from .address import Location
from .affiliation import Affiliation
from .alias import Alias
# ... other imports ...
from .vehicle import Vehicle  # Add your import here
```

Затем добавьте имя типа в список `__all__`:

```python
__all__ = [
    "Location",
    "Affiliation",
    "Alias",
    # ... other types ...
    "Vehicle",  # Add your type here
]
```

Список `__all__` явно определяет, что экспортируется при `from flowsint_types import *`. Хотя импорт через звёздочку не всегда рекомендуется, так вы гарантируете, что тип корректно доступен из пакета.

Обратите внимание: декоратор `@flowsint_type` уже автоматически регистрирует тип в `TYPE_REGISTRY` при импорте модуля, поэтому явный импорт в `__init__.py` обеспечивает загрузку типа при запуске наряду со всеми остальными типами.

### Установка пакета

После этих изменений пакет нужно переустановить, чтобы они вступили в силу:

```bash
make prod
#or
cd flowsint-types
poetry install
```

Это обновляет пакет в вашей среде разработки, чтобы обогатители и API могли импортировать новый тип.

## Интеграция с API

Последний шаг — сделать тип доступным через API, чтобы фронтенды могли его обнаруживать и создавать экземпляры.

### Категоризация типа

API организует типы в логические категории, которые отображаются во фронтенде. В методе `TypeRegistryService._get_category_definitions()` (в `flowsint-core/src/flowsint_core/core/services/type_registry_service.py`) есть список словарей категорий. Нужно добавить свой тип в подходящую категорию или создать новую.

Список `children` каждой категории содержит кортежи `(TypeName, label_key, icon)`:
- **TypeName**: имя класса вашего типа в PascalCase (например, `"Vehicle"`)
- **label_key**: имя поля, используемого как ключ отображения (например, `"license_plate"`)
- **icon**: необязательное переопределение значка или `None`, чтобы использовать имя типа в нижнем регистре как значок

Можно добавить тип в существующую категорию или создать новую.

```python
def _get_category_definitions(self) -> List[Dict[str, Any]]:
    """Get the category definitions for types."""
    return [
        {
            "id": uuid4(),
            "type": "global",
            "key": "global_category",
            "icon": "phrase",
            "label": "Global",
            "fields": [],
            "children": [
                ("Phrase", "text", None),
                ("Location", "address", None),
            ],
        },
        {
            "id": uuid4(),
            "type": "person",
            "key": "person_category",
            "icon": "individual",
            "label": "Identities & Entities",
            "fields": [],
            "children": [
                ("Individual", "full_name", None),
                ("Username", "value", "username"),
                ("Organization", "name", None),
            ],
        },
    ...
```


### Доступные категории

Сейчас Flowsint организует типы в такие стандартные категории:

- **Global** содержит универсальные типы, такие как Location и Phrase, которые не вписываются в другие категории.

- **Identities & Entities** включает Individual, Username и Organization для представления людей и групп.

- **Organization** содержит Organization для специализированного поиска по организациям.

- **Communication & Contact** охватывает Phone, Email, Username, SocialAccount и Message для данных, связанных со связью и контактами.

- **Network** объединяет все сетевые типы, включая ASN, CIDR, Domain, Website, Ip, Port, DNSRecord, SSLCertificate и WebTracker.

- **Security & Access** группирует типы, связанные с безопасностью: Credential, Session, Device, Malware и Weapon.

- **Files & Documents** содержит Document и File для представления цифровых файлов.

- **Financial Data** включает BankAccount и CreditCard для финансовой информации.

- **Leaks** охватывает данные об утечках с типом Leak.

- **Crypto** содержит типы, связанные с криптовалютами, включая CryptoWallet, CryptoWalletTransaction и CryptoNFT.

Можно добавить тип в любую из этих категорий или создать новую, если ни одна не подходит.

<Alert variant="info">
    <AlertTitle>Зарегистрированные, но некатегоризированные типы</AlertTitle>
    <AlertDescription>
    Некоторые типы зарегистрированы (через `@flowsint_type`) и используются как входы или выходы обогатителей, но намеренно не включены ни в одну встроенную категорию: `Affiliation`, `Alias`, `Breach`, `Gravatar`, `ReputationScore`, `RiskProfile`, `Script` и `Whois`. Они отображаются в графе как узлы, создаваемые обогатителями (например, `Whois` создаётся `domain_to_whois`), но не появляются в выборе типа, пока вы не добавите их в `_get_category_definitions()`.

## Полные примеры

Рассмотрим несколько полных примеров из практики, иллюстрирующих разные шаблоны.

### Пример простого типа

Самые простые типы содержат одно-два обязательных поля и минимум сложности:

```python
from pydantic import Field, model_validator
from typing import Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type

@flowsint_type
class Hashtag(FlowsintType):
    """Represents a social media hashtag."""

    tag: str = Field(
        ...,
        description="Hashtag text without the # symbol",
        title="Hashtag",
        json_schema_extra={"primary": True}
    )

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this hashtag."""
        self.nodeLabel = f"#{self.tag}"
        return self
```

### Тип с валидацией

Этот пример показывает тип «номер соцстрахования» с проверкой формата:

```python
from pydantic import Field, field_validator, model_validator
from typing import Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type
import re

@flowsint_type
class SocialSecurityNumber(FlowsintType):
    """Represents a US Social Security Number."""

    ssn: str = Field(
        ...,
        description="Social Security Number in format XXX-XX-XXXX",
        title="SSN",
        json_schema_extra={"primary": True}
    )

    @field_validator('ssn')
    @classmethod
    def validate_ssn_format(cls, v: str) -> str:
        """Validate SSN format and normalize to standard format."""
        clean = v.replace("-", "").replace(" ", "")

        if not re.match(r"^\d{9}$", clean):
            raise ValueError(
                "SSN must be exactly 9 digits (format: XXX-XX-XXXX or XXXXXXXXX)"
            )

        return f"{clean[:3]}-{clean[3:5]}-{clean[5:]}"

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this SSN."""
        # Mask most digits for privacy
        self.nodeLabel = f"SSN ***-**-{self.ssn[-4:]}"
        return self
```

### Тип со связанными типами

Этот пример показывает, как типы могут ссылаться на другие типы, чтобы строить насыщенные модели данных:

```python
from pydantic import Field, model_validator
from typing import Optional, Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type
from .email import Email
from .domain import Domain

@flowsint_type
class Whois(FlowsintType):
    """Represents WHOIS domain registration information."""

    domain: Domain = Field(
        ...,
        description="Domain",
        title="Domain",
    )

    registrar: Optional[str] = Field(
        None,
        description="Name of the domain registrar",
        title="Registrar"
    )

    email: Optional[Email] = Field(
        None,
        description="Contact email address from WHOIS record",
        title="Contact Email"
    )

    creation_date: Optional[str] = Field(
        None,
        description="Date when the domain was first registered",
        title="Creation Date"
    )

    expiration_date: Optional[str] = Field(
        None,
        description="Date when the domain registration expires",
        title="Expiration Date"
    )

    @model_validator(mode='after')
    def compute_label(self) -> Self:
        """Compute label for this WHOIS record."""
        if self.registrar:
            self.nodeLabel = f"{self.domain.domain} (via {self.registrar})"
        else:
            self.nodeLabel = f"WHOIS: {self.domain.domain}"
        return self
```

### Сложный тип с коллекциями

Этот пример демонстрирует тип со списками других типов и насыщенными метаданными:

```python
from pydantic import Field, model_validator
from typing import Optional, List, Dict, Any, Self
from .flowsint_base import FlowsintType
from .registry import flowsint_type
from .individual import Individual
from .address import Location

@flowsint_type
class Organization(FlowsintType):
    """Represents an organization with comprehensive business information."""

    name: str = Field(
        ...,
        description="Legal name of the organization",
        title="Organization Name",
        json_schema_extra={"primary": True}
    )

    registration_number: Optional[str] = Field(
        None,
        description="Official business registration number",
        title="Registration Number"
    )

    headquarters: Optional[Location] = Field(
        None,
        description="Primary headquarters location",
        title="Headquarters"
    )

    executives: List[Individual] = Field(
        default_factory=list,
        description="List of company executives and board members",
        title="Executives"
    )

    locations: List[Location] = Field(
        default_factory=list,
        description="All office and facility locations",
        title="Locations"
    )

    employee_count: Optional[int] = Field(
        None,
        description="Total number of employees",
        title="Employee Count"
    )

    revenue: Optional[float] = Field(
        None,
        description="Annual revenue in USD",
        title="Revenue"
    )

    industry: Optional[str] = Field(
        None,
        description="Primary industry sector",
        title="Industry"
    )

    metadata: Dict[str, Any] = Field(
        default_factory=dict,
        description="Additional metadata and custom fields",
        title="Metadata"
    )

    @model_validator(mode='after')
    def compute_label(self) -> Self:

        if self.industry:

        else:
            self.nodeLabel = self.name
        return self
```

## Лучшие практики и типовые шаблоны

### Документация

Держите документацию на переднем плане. У каждого типа должны быть:
- Понятный docstring, объясняющий, что он представляет
- Описательный параметр `description` у каждого поля (для документации API)
- Осмысленный параметр `title` у каждого поля (для подписей в интерфейсе)

Будущие разработчики (включая вас самих) скажут вам спасибо за эту ясность.

### Обязательные и необязательные поля

Хорошо продумайте, что должно быть обязательным, а что нет:
- **Обязательные поля** (с `...`): только поля, однозначно идентифицирующие сущность или абсолютно необходимые
- **Необязательные поля** (с `Optional[Type]` и `None`): большинство остальных полей должны быть необязательными, потому что сбор информации идёт постепенно, и полной информации заранее у вас почти никогда нет

### Всегда наследуйтесь от FlowsintType и используйте декоратор

Никогда не наследуйтесь напрямую от `BaseModel` Pydantic. Всегда используйте `FlowsintType` и декоратор `@flowsint_type`:

```python
# Correct
from .flowsint_base import FlowsintType
from .registry import flowsint_type

@flowsint_type
class MyType(FlowsintType):
    ...

# Wrong - missing decorator
from .flowsint_base import FlowsintType

class MyType(FlowsintType):  # Not registered!
    ...

# Wrong - wrong base class
from pydantic import BaseModel

class MyType(BaseModel):  # Missing FlowsintType features
    ...
```

### Всегда реализуйте compute_label

Каждый тип обязан реализовать метод `compute_label`, задающий `nodeLabel`, отображаемый в интерфейсе и на графе:

```python
@model_validator(mode='after')
def compute_label(self) -> Self:
    """Compute a human-readable label."""
    # Handle None values gracefully
    if self.optional_field:
        self.nodeLabel = f"{self.primary_field} ({self.optional_field})"
    else:
        self.nodeLabel = self.primary_field
    return self
```

**Лучшие практики для меток:**
- Делайте их краткими, но информативными
- Корректно обрабатывайте None для необязательных полей
- Ставьте самую важную информацию в начало
- Думайте о том, что пользователям нужно видеть на графе с первого взгляда

### Подсказки типов и валидация

Используйте подсказки типов везде. Они дают:
- Автоматическую валидацию
- Лучшую поддержку IDE и автодополнение
- Встроенную документацию
- Проверку типов во время выполнения через Pydantic

Для изменяемых значений по умолчанию, таких как списки и словари, всегда используйте `default_factory`:

```python
# Correct
tags: List[str] = Field(default_factory=list)
metadata: Dict[str, Any] = Field(default_factory=dict)

# Wrong - all instances will share the same object!
tags: List[str] = Field(default=[])
metadata: Dict[str, Any] = Field(default={})
```

### Импорт других типов

При ссылках на другие типы Flowsint используйте относительные импорты, чтобы избежать проблем с циклическими импортами:

```python
# Correct
from .email import Email
from .phone import Phone

# Avoid
from flowsint_types import Email, Phone  # Can cause circular imports
```

Если возникли проблемы с циклическими импортами, можно использовать прямые ссылки (строки) в подсказках типов и вызвать `model_rebuild()` в конце модуля.

### Пользовательская валидация

Рассмотрите добавление собственных валидаторов для сложной логики проверки, выходящей за рамки простой проверки типов:

```python
@field_validator('email')
@classmethod
def validate_email(cls, v: str) -> str:
    """Validate and normalize email format."""
    if not is_valid_email(v):
        raise ValueError("Invalid email format")
    return v.lower()
```

Это держит логику валидации рядом с определением типа и обеспечивает целостность данных во всей системе.

### Порядок выполнения

Помните порядок, в котором Pydantic обрабатывает ваш тип:
1. **Валидаторы полей** (`@field_validator`) выполняются первыми, проверяя и при необходимости преобразуя отдельные поля
2. **Валидаторы модели** (`@model_validator`) выполняются после, работая со всей проверенной моделью
3. Ваш метод `compute_label` (валидатор модели) выполняется последним, когда все поля уже проверены

Это значит, что в `compute_label` можно безопасно обращаться к проверенным значениям полей.

## Тестирование типа

Тесты типов гарантируют их корректную работу и помогают выявлять ошибки на ранней стадии. Создайте тестовый файл в `flowsint-types/tests/`, имя которого соответствует файлу вашего типа.

### Базовая структура теста

```python
# flowsint_types/tests/test_vehicle.py
from flowsint_types import Vehicle
import pytest

def test_vehicle_creation():

    assert vehicle.year == 2020

def test_vehicle_missing_required_field():

```

Метка критична для отображения в интерфейсе, поэтому тестируйте её тщательно:

### Тестирование валидаторов полей

Если у вашего типа есть пользовательские валидаторы, тестируйте и корректные, и некорректные входные данные:

```python
# tests/test_username.py
from flowsint_types import Username
import pytest
```

## Решение типичных проблем

### Ошибки импорта

Если после создания типа возникают ошибки импорта, убедитесь, что вы выполнили `poetry install` в каталоге `flowsint-types`. Пакет нужно переустановить, чтобы изменения вступили в силу:

```bash
cd flowsint-types
poetry install
```

### Тип не появляется в API

Если ваш тип не появляется в API, проверьте, что вы:
1. Пометили его декоратором `@flowsint_type`
2. Импортировали его в `flowsint_types/__init__.py`
3. Добавили его в список `__all__` в `flowsint_types/__init__.py`
4. Добавили его в подходящую категорию в `_get_category_definitions()` в `flowsint-core/src/flowsint_core/core/services/type_registry_service.py`

### Тип не найден в TYPE_REGISTRY

Если `TYPE_REGISTRY.get("MyType")` возвращает `None`:
- Убедитесь, что к классу применён декоратор `@flowsint_type`
- Убедитесь, что модуль импортируется (в `__init__.py` или через `load_all_types()`)
- Проверьте, нет ли в файле вашего типа ошибок импорта, мешающих загрузке модуля

### Ошибки валидации

При ошибках валидации проверьте, что вы используете:
- Многоточие (`...`) для обязательных полей
- `None` для необязательных полей
- `Optional[Type]` в подсказках типов необязательных полей

### Узлы не появляются в графе

Если экземпляры вашего типа не появляются в Neo4j:
- **Проверьте обогатитель**: убедитесь, что обогатители с этим типом вызывают `self.create_node(instance)`
- **Проверьте созданный узел**: убедитесь, что формат созданного узла корректен, нет пропущенных обязательных полей и т. д.

### Метка отображается неправильно

Если метки отображаются в интерфейсе или графе неправильно:
- **Нет compute_label**: убедитесь, что вы реализовали метод с `@model_validator(mode='after')`
- **Неверное имя поля**: убедитесь, что вы задаёте `self.nodeLabel`, а не `self.label`
- **Не возвращается Self**: метод должен возвращать `self`
- **Обработка None**: проверьте, что вы корректно обрабатываете значения None для необязательных полей
- **Имя метода**: метод должен называться именно `compute_label`

### Циклические импорты

Если вы сталкиваетесь с проблемами циклических импортов:
- Используйте относительные импорты (`from .email import Email`) вместо абсолютных
- При необходимости используйте прямые ссылки (строковые подсказки типов)
- Вызовите `model_rebuild()` в конце модуля, чтобы разрешить прямые ссылки

### Ошибки обогатителей с вашим типом

Если обогатители падают при использовании вашего типа:
- **Сбои валидации**: ваши валидаторы полей могут быть слишком строгими; посмотрите сообщения об ошибках валидатора в логах
- **Проблемы с вложенными объектами**: при передаче вложенных типов Flowsint передавайте объект целиком, не пересоздавайте его
- **Извлечение первичного ключа**: сервису графа нужно извлечь примитивное значение из вашего основного поля

## Дальнейшие шаги

Когда вы создали и зарегистрировали тип, его можно использовать в обогатителях для построения процессов сбора информации. Типы служат спецификациями входа и выхода обогатителей и определяют структуру узлов в графовой базе данных Neo4j.

### Контрольный список для новых типов

Прежде чем считать тип завершённым, убедитесь, что вы:

- Пометили декоратором `@flowsint_type`
- Унаследовали от `FlowsintType`
- Пометили ровно одно поле как основное через `json_schema_extra={"primary": True}`
- Реализовали метод `compute_label`, который задаёт `self.nodeLabel` и корректно обрабатывает None
- Указали `description` и `title` для всех полей
- Использовали `default_factory` для полей-списков и полей-словарей
- Написали тесты на создание, валидацию, основное поле и вычисление метки
- Экспортировали тип в `flowsint_types/__init__.py`
- Добавили его в категорию в `flowsint-core/src/flowsint_core/core/services/type_registry_service.py`
- Выполнили `poetry install`, чтобы тип стал доступен

### Что изучить дальше

Вам также может быть интересно:

- **Создание обогатителей**: используйте свой тип как вход/выход в собственных обогатителях
- **Пользовательские типы через API**: Flowsint поддерживает создание типов во время работы через JSON Schema (см. `flowsint-core/src/flowsint_core/core/models.py`)
- **Формат графа**: узнайте о [формате узлов и рёбер](/docs/developers/graph-format), используемом во фронтенде
- **Схемы типов**: поймите, как схемы Pydantic используются для валидации API

### Итоговые мысли

Помните, что типы — это основа всего во Flowsint:
- **Хорошо спроектированные типы** упрощают написание обогатителей
- **Чёткие основные поля** обеспечивают правильную идентификацию узлов в графе
- **Осмысленные метки** делают интерфейс и графовую базу данных интуитивнее
- **Тщательная валидация** обеспечивает целостность данных на всей платформе

Освоив эти концепции, вы готовы создавать мощные и надёжные типы, которые сделают всю платформу Flowsint эффективнее для сбора информации.

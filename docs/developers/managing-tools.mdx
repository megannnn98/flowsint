## Что такое инструменты

Инструменты во Flowsint — это слои абстракции между обогатителями и внешними системами. Они предоставляют единый интерфейс для запуска Docker-контейнеров, вызова API и работы с Python-библиотеками. Если обогатители отвечают за высокоуровневую оркестрацию и операции с графовой базой данных, то инструменты занимаются исключительно выполнением внешних команд и возвратом необработанных результатов.

Каждый инструмент реализует базовый интерфейс с методами для именования, категоризации и выполнения. Инструменты ничего не знают о типах Pydantic, графах Neo4j и общей архитектуре Flowsint. Они лишь оборачивают внешнюю функциональность и возвращают данные.

Сейчас во Flowsint есть инструменты для перебора поддоменов, сканирования портов, DNS-запросов, WHOIS-запросов, обхода сайтов и бизнес-аналитики.

## Архитектура инструментов

Система инструментов имеет двухуровневую иерархию наследования. На базовом уровне находится абстрактный класс `Tool`, определяющий интерфейс, который обязан реализовать каждый инструмент. Для инструментов, работающих в Docker-контейнерах, есть промежуточный класс `DockerTool`, который берёт на себя весь жизненный цикл контейнера.

### Базовый класс Tool

Каждый инструмент наследуется от абстрактного класса `Tool`, который находится в `flowsint-enrichers/src/tools/base.py`. Вот как он выглядит:

```python
from abc import ABC, abstractmethod
from typing import Any

class Tool(ABC):
    """Abstract base class for all tools."""

    @classmethod
    @abstractmethod
    def name(cls) -> str:
        """Return the tool name."""
        pass

    @classmethod
    @abstractmethod
    def category(cls) -> str:
        """Return the tool category."""
        pass

    @classmethod
    @abstractmethod
    def description(cls) -> str:
        """Return a description of what the tool does."""
        pass

    @classmethod
    @abstractmethod
    def version(cls) -> str:
        """Return the tool version."""
        pass

    @abstractmethod
    def launch(self, value: str, *args, **kwargs) -> Any:
        """Execute the tool and return results."""
        pass
```

Любой создаваемый вами инструмент должен реализовать эти пять методов. Первые четыре — методы класса, предоставляющие метаданные об инструменте. Метод `launch` — это то место, где выполняется настоящая работа.

### Класс DockerTool

Большинство инструментов безопасности и разведки запускаются в Docker-контейнерах ради изоляции и переносимости. Класс `DockerTool` в `flowsint-enrichers/src/tools/dockertool.py` предоставляет всю инфраструктуру для запуска контейнеризованных инструментов.

Наследуясь от `DockerTool`, вы автоматически получаете управление образами, запуск контейнеров, монтирование томов, обработку переменных окружения и очистку. Вам остаётся указать имя Docker-образа и реализовать построение команды.

Вот упрощённый обзор того, что предоставляет `DockerTool`:


Метод `launch` в `DockerTool` отвечает за запуск контейнера. Он настраивает окружение, при необходимости монтирует тома, запускает контейнер, перехватывает вывод и затем выполняет очистку.

## Создание простого инструмента на основе API

Начнём с более простого случая — инструмента, который обращается к внешнему API. Создадим гипотетический инструмент для запросов к сервису threat intelligence.

### Структура файлов

Создайте новый Python-файл в подходящем каталоге категории внутри `flowsint-enrichers/src/tools/`. Для инструмента, связанного с безопасностью, можно использовать `tools/security/`:

```bash
cd flowsint-enrichers/src/tools/security/
touch threat_intel.py
```

Если каталога категории нет, сначала создайте его и добавьте файл `__init__.py`, чтобы сделать его Python-пакетом.

### Базовая реализация

Вот полный пример инструмента на основе API:

```python
from tools.base import Tool
from typing import Any, Dict, List, Optional
import requests

class ThreatIntelTool(Tool):
    """Query threat intelligence data from an external API."""

    api_endpoint = "https://api.threatintel.example.com/v1"

    @classmethod
    def name(cls) -> str:
        """Return the tool name."""
        return "threatintel"

    @classmethod
    def category(cls) -> str:
        """Return the category this tool belongs to."""
        return "Threat Intelligence"

    @classmethod
    def description(cls) -> str:
        """Return a description of what this tool does."""
        return "Queries threat intelligence data for IPs, domains, and hashes"

    @classmethod
    def version(cls) -> str:
        """Return the tool version."""
        return "1.0.0"

    def launch(
        self,
        indicator: str,
        indicator_type: str = "ip",
        api_key: Optional[str] = None
    ) -> List[Dict[str, Any]]:
        """
        Query the threat intelligence API.

        Args:
            indicator: The indicator to query (IP, domain, hash, etc.)
            indicator_type: Type of indicator (ip, domain, hash)
            api_key: API key for authentication

        Returns:
            List of threat intelligence records
        """
        if not api_key:
            raise ValueError("API key is required")

        headers = {
            "Authorization": f"Bearer {api_key}",
            "Content-Type": "application/json"
        }

        params = {
            "indicator": indicator,
            "type": indicator_type
        }

        try:
            response = requests.get(
                f"{self.api_endpoint}/query",
                headers=headers,
                params=params,
                timeout=30
            )
            response.raise_for_status()
            return response.json().get("results", [])

        except requests.exceptions.RequestException as e:
            print(f"Error querying threat intel API: {e}")
            return []
```

Этот инструмент следует простому шаблону. Методы класса предоставляют метаданные, которые используют обогатители и реестр. Метод `launch` реализует само взаимодействие с API: обрабатывает аутентификацию, выполняет запрос и возвращает структурированные данные.

Обратите внимание, что инструмент возвращает простые структуры данных Python — списки и словари. Инструменты не знают о типах Pydantic и моделях Flowsint. Это задача обогатителя.

## Создание инструмента на основе Docker

Инструменты на основе Docker встречаются во Flowsint чаще, потому что большинству утилит разведки нужны определённые зависимости и изолированное окружение. Разберём создание инструмента, который оборачивает гипотетический сканер поддоменов в Docker.

### Настройка класса

Начните с наследования от `DockerTool` и укажите информацию о Docker-образе:

```python
from tools.dockertool import DockerTool
from typing import List, Optional, Any

class MySubdomainTool(DockerTool):
    """Wrapper for a Docker-based subdomain enumeration tool."""

    image = "org/subdomain-scanner"
    default_tag = "latest"

    def __init__(self):
        """Initialize the tool with Docker image information."""
        super().__init__(self.image, self.default_tag)
```

Атрибуты класса `image` и `default_tag` сообщают `DockerTool`, какой Docker-образ использовать. При создании экземпляра инструмента он автоматически подключится к демону Docker.

### Реализация метода launch

Метод `launch` должен построить команду, которая выполняется внутри контейнера, и обработать результаты:

```python
    def launch(
        self,
        domain: str,
        timeout: int = 300,
        wordlist: Optional[str] = None
    ) -> List[str]:
        """
        Enumerate subdomains for a given domain.

        Args:
            domain: Target domain to enumerate
            timeout: Maximum execution time in seconds
            wordlist: Optional path to custom wordlist file

        Returns:
            List of discovered subdomain strings
        """
        # Ensure the Docker image is available
        if not self.is_installed():
            self.install()

        # Build the command that runs inside the container
        command = f"-d {domain}"

        if wordlist:
            command += f" -w {wordlist}"

        # Add JSON output flag for easier parsing
        command += " -json"

        # Execute the container
        try:
            result = super().launch(
                command=command,
                timeout=timeout
            )

            # Parse the output
            subdomains = self._parse_output(result)
            return subdomains

        except Exception as e:
            print(f"Error running subdomain scanner: {e}")
            return []

    def _parse_output(self, output: str) -> List[str]:
        """Parse the tool output and extract subdomains."""
        import json

        subdomains = []
        for line in output.strip().split('\n'):
            if not line:
                continue
            try:
                data = json.loads(line)
                if 'subdomain' in data:
                    subdomains.append(data['subdomain'])
            except json.JSONDecodeError:
                continue

        return list(set(subdomains))  # Remove duplicates
```

Эта реализация демонстрирует несколько важных приёмов. Во-первых, она проверяет, установлен ли Docker-образ, и при необходимости скачивает его. Во-вторых, формирует строку команды, которая будет выполнена в контейнере. В-третьих, вызывает метод `launch` родительского класса, чтобы выполнить сам запуск контейнера. Наконец, разбирает вывод и преобразует его в чистую структуру данных Python.

### Работа с томами

Некоторым инструментам нужен доступ к файлам хост-системы. Тома можно монтировать при вызове родительского метода `launch`:

```python
    def launch(self, domain: str, wordlist_path: str = None) -> List[str]:
        """Run the tool with optional wordlist file."""

        command = f"-d {domain}"
        volumes = None

        if wordlist_path:
            # Mount the wordlist file into the container
            volumes = {
                wordlist_path: {
                    'bind': '/wordlist.txt',
                    'mode': 'ro'  # read-only
                }
            }
            command += " -w /wordlist.txt"

        result = super().launch(
            command=command,
            volumes=volumes
        )

        return self._parse_output(result)
```

Словарь томов сопоставляет пути на хосте с путями в контейнере. Режим монтирования можно задать как 'ro' (только чтение) или 'rw' (чтение и запись).

### Использование переменных окружения

Для инструментов, которым нужны API-ключи или конфигурация через переменные окружения:

```python
    def launch(self, domain: str, api_key: Optional[str] = None) -> List[str]:
        """Run the tool with optional API key for enhanced scanning."""

        command = f"-d {domain}"
        environment = {}

        if api_key:
            environment['API_KEY'] = api_key

        result = super().launch(
            command=command,
            environment=environment
        )

        return self._parse_output(result)
```

## Тестирование инструмента

Тесты инструмента помогают убедиться, что он работает правильно, и облегчают обнаружение регрессий. Создайте тестовый файл в `flowsint-enrichers/tests/tools/`, повторяющий расположение вашего инструмента:

```python
# tests/tools/security/test_threat_intel.py
from tools.security.threat_intel import ThreatIntelTool
import pytest

def test_tool_metadata():
    """Test that tool metadata is correctly defined."""
    assert ThreatIntelTool.name() == "threatintel"
    assert ThreatIntelTool.category() == "Threat Intelligence"
    assert "threat" in ThreatIntelTool.description().lower()

def test_tool_launch_requires_api_key():
    """Test that launch method requires an API key."""
    tool = ThreatIntelTool()
    with pytest.raises(ValueError):
        tool.launch("192.0.2.1")

def test_tool_launch_with_api_key(monkeypatch):
    """Test successful API query with mocked response."""
    tool = ThreatIntelTool()

    # Mock the requests.get call
    def mock_get(*args, **kwargs):
        class MockResponse:
            def raise_for_status(self):
                pass
            def json(self):
                return {"results": [{"indicator": "192.0.2.1", "threat_level": "high"}]}
        return MockResponse()

    monkeypatch.setattr("requests.get", mock_get)

    results = tool.launch("192.0.2.1", api_key="test_key")
    assert len(results) == 1
    assert results[0]["indicator"] == "192.0.2.1"
```

Для инструментов на основе Docker тесты требуют запущенного Docker:

```python
# tests/tools/network/test_my_subdomain_tool.py
from tools.network.my_subdomain_tool import MySubdomainTool
import pytest

@pytest.mark.docker
def test_tool_install():
    """Test that the Docker image can be pulled."""
    tool = MySubdomainTool()
    tool.install()
    assert tool.is_installed()

@pytest.mark.docker
def test_tool_launch():
    """Test running the tool against a domain."""
    tool = MySubdomainTool()
    results = tool.launch("example.com")
    assert isinstance(results, list)
```

Декоратор `@pytest.mark.docker` помогает отделить тесты, которым нужен Docker, от остальных.

## Лучшие практики

При создании инструментов стремитесь к простоте и единственной ответственности. Каждый инструмент должен оборачивать ровно одну внешнюю утилиту или один API. Не пытайтесь объединять несколько источников данных в одном инструменте — для этого есть обогатители.

Всегда корректно обрабатывайте ошибки. Сетевые запросы падают, Docker-контейнеры аварийно завершаются, а API возвращают неожиданные данные. Ваш инструмент должен перехватывать такие ошибки, адекватно их логировать и возвращать пустые результаты или выбрасывать понятные исключения, а не падать.

Возвращайте из метода `launch` простые структуры данных: списки, словари, строки и числа. Не возвращайте модели Pydantic и другие сложные объекты. Помните, что инструменты — это низкоуровневые утилиты, на которых строятся обогатители.

Для Docker-инструментов всегда проверяйте, установлен ли образ, прежде чем его запускать. Шаблон «проверить `is_installed()` и при необходимости вызвать `install()`» гарантирует работу инструмента даже при чистой установке.

При разборе вывода инструмента будьте осторожны. Внешние инструменты могут возвращать неожиданные форматы, частичные результаты или мусор. Проверяйте и очищайте вывод перед возвратом. Оборачивайте логику разбора в блоки try-except.

Подробно документируйте инструмент. Docstring'и и описания параметров помогают другим разработчикам понять, как им пользоваться. Будущие обогатители будут опираться на эту документацию.

## Интеграция инструмента

В отличие от типов, инструменты не нужно явно регистрировать в центральном реестре. Обогатители импортируют и используют их напрямую. Когда вы создаёте обогатитель, использующий новый инструмент, достаточно его импортировать:

```python
# In an enricher file
from tools.security.threat_intel import ThreatIntelTool

class IpToThreatIntelEnricher(Enricher):
    async def scan(self, data: List[Ip]) -> List[ThreatReport]:
        tool = ThreatIntelTool()
        results = []

        for ip in data:
            intel = tool.launch(
                indicator=ip.address,
                indicator_type="ip",
                api_key=api_key
            )
            # Process results...

        return results
```

Обогатитель создаёт экземпляр вашего инструмента, вызывает его метод `launch` с нужными параметрами и преобразует результаты в типы Flowsint.

## Типовые шаблоны

Несколько шаблонов часто встречаются в инструментах Flowsint. Их понимание поможет писать инструменты, естественно вписывающиеся в экосистему.

### Шаблон «проверка установки»

Большинство Docker-инструментов начинают `launch` по такому шаблону:

```python
def launch(self, ...):
    if not self.is_installed():
        self.install()

    # Continue with execution
```

Это гарантирует, что Docker-образ доступен, прежде чем его запускать.

### Шаблон «построитель команды»

Сложные инструменты часто строят команду постепенно, в зависимости от параметров:

```python
def launch(self, target: str, mode: str = "fast", verbose: bool = False):
    command = f"-target {target}"

    if mode == "thorough":
        command += " --thorough"

    if verbose:
        command += " -v"

    result = super().launch(command)
```

### Шаблон «парсер вывода»

Многие инструменты разделяют выполнение и разбор:

```python
def launch(self, ...):
    raw_output = super().launch(command)
    return self._parse_output(raw_output)

def _parse_output(self, output: str) -> List[Dict]:
    """Parse raw tool output into structured data."""
    # Parsing logic here
```

Такое разделение упрощает тестирование и сопровождение кода.

## Дальнейшие шаги

Когда вы создали инструмент и протестировали его, можно строить обогатители, которые его используют. Обогатители оркеструют один или несколько инструментов для сбора информации, проверяют результаты, преобразуют их в типы Flowsint и создают узлы и связи в графовой базе данных.

Если вашему инструменту нужны API-ключи или другие секреты, обогатители могут получать их через систему хранилища (vault). Реализуя обогатитель с вашим инструментом, можно определить параметры типа `vaultSecret`, которые берут учётные данные из зашифрованного хранилища пользователя.

Помните, что инструменты — лишь один слой архитектуры Flowsint. Они предоставляют сырые возможности, а обогатители добавляют аналитику и логику построения графа, которые делают платформу мощной.

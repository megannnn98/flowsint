## Что такое обогатители

Обогатители — это слой высокоуровневой бизнес-логики во Flowsint. Если типы описывают структуры данных, а инструменты оборачивают внешние утилиты, то обогатители оркеструют весь процесс сбора информации. Обогатитель принимает входные данные одного типа, обрабатывает их через различные инструменты или API, проверяет и обогащает результаты, создаёт узлы и связи в графовой базе данных и возвращает структурированный результат.

Каждый обогатитель во Flowsint следует двухфазной модели выполнения. Фаза сканирования (scan) содержит основную логику обогащения: здесь запускаются инструменты, вызываются API и собираются данные. Затем фаза постобработки (postprocess) создаёт узлы и связи в графе Neo4j и возвращает обработанные результаты. Проверка и нормализация входных данных выполняются автоматически через валидацию типов Pydantic.

Обогатители принципиально отличаются от инструментов. Инструменты — низкоуровневые обёртки, возвращающие сырые данные без знания об экосистеме Flowsint. Обогатители — высокоуровневые процессы, которые понимают типы, создают узлы графа, обрабатывают параметры и оркеструют несколько инструментов. Когда нужно добавить новый источник данных, вы создаёте инструмент. Когда нужно добавить новый процесс сбора информации — создаёте обогатитель.

## Архитектура обогатителей

Система обогатителей построена вокруг абстрактного базового класса, который определяет интерфейс и ход выполнения. Каждый создаваемый вами обогатитель наследуется от этого базового класса и реализует определённые методы.

### Базовый класс Enricher

Базовый класс находится в `flowsint-core/src/flowsint_core/core/enricher_base.py` и обеспечивает каркас для всех обогатителей. Вот как выглядит минимальный обогатитель:

```python
from typing import List
from flowsint_core.core.enricher_base import Enricher
from flowsint_enrichers.registry import flowsint_enricher
from flowsint_types import Domain, Ip

@flowsint_enricher
class MyEnricher(Enricher):
    """Description of what this enricher does."""

    # Define input and output types as base types (not lists)
    InputType = Domain
    OutputType = Ip

    @classmethod
    def name(cls) -> str:
        """Unique identifier for this enricher."""
        return "domain_to_ip"

    @classmethod
    def category(cls) -> str:
        """Category this enricher belongs to."""
        return "Domain"

    @classmethod
    def key(cls) -> str:
        """Primary key field name for this enricher."""
        return "domain"

    async def scan(self, data: List[InputType]) -> List[OutputType]:
        """Core enriching logic."""
        pass

    def postprocess(self, results: List[OutputType], input_data: List[InputType]) -> List[OutputType]:
        """Create graph nodes and relationships."""
        pass

# Export types for easy access
InputType = MyEnricher.InputType
OutputType = MyEnricher.OutputType
```

Атрибуты класса `InputType` и `OutputType` определяют, какие данные обогатитель принимает и возвращает. Это должны быть типы Pydantic из пакета `flowsint-types`, заданные как базовые типы (например, `Domain`, а не `List[Domain]`). Базовый класс использует эти определения типов, чтобы автоматически генерировать JSON-схемы для API и выполнять валидацию.

В конце файла нужно экспортировать типы, чтобы они были удобно доступны другим модулям.

### Две фазы

Понимание двух фаз выполнения крайне важно для написания эффективных обогатителей.

**Сканирование (scan)** — здесь выполняется основная работа. Этот асинхронный метод получает проверенные входные данные в виде списка экземпляров `InputType` и выполняет вашу логику сбора информации. Вы можете создавать экземпляры инструментов, вызывать внешние API, обрабатывать результаты и формировать выходные данные. Эта фаза должна заниматься исключительно сбором и обработкой данных, не заботясь о графовой базе. Базовый класс автоматически выполняет проверку входных данных через Pydantic до начала фазы сканирования.

**Постобработка (postprocess)** создаёт структуру в графовой базе данных. После завершения сканирования этот метод получает и результаты, и исходные входные данные. Он создаёт узлы Neo4j для каждой сущности, устанавливает связи между ними и возвращает итоговые результаты. Такое разделение отделяет логику графа от бизнес-логики.

## Создание простого обогатителя

Пройдём весь путь создания полноценного обогатителя с нуля. Мы построим обогатитель, который преобразует домены в IP-адреса с помощью DNS-разрешения.

### Подготовка структуры файлов

Обогатители организованы по входному типу. Создайте новый файл в подходящем каталоге внутри `flowsint-enrichers/src/flowsint_enrichers/`:

```bash
cd flowsint-enrichers/src/flowsint_enrichers/domain/
touch to_ip.py
```

Если вы создаёте обогатитель для нового входного типа, возможно, сначала придётся создать новый каталог.

### Реализация базовой структуры

Начните с импортов и определения класса:

```python
import socket
from typing import List
from flowsint_enrichers.registry import flowsint_enricher
from flowsint_core.core.enricher_base import Enricher
from flowsint_core.core.logger import Logger
from flowsint_types import Domain, Ip

@flowsint_enricher
class DomainToIpEnricher(Enricher):
    """Resolves domain names to their IP addresses using DNS."""

    # Define types as base types (not lists)
    InputType = Domain
    OutputType = Ip

    @classmethod
    def name(cls) -> str:
        return "domain_to_ip"

    @classmethod
    def category(cls) -> str:
        return "Domain"

    @classmethod
    def key(cls) -> str:
        return "domain"

    @classmethod
    def documentation(cls) -> str:
        return """
        This enricher resolves domain names to their IP addresses using
        standard DNS queries. It accepts a list of domains and returns
        the corresponding IP addresses.
        """

# Export types at the end of the file
InputType = DomainToIpEnricher.InputType
OutputType = DomainToIpEnricher.OutputType
```

Метод `name()` возвращает уникальный идентификатор обогатителя. Используйте нижний регистр и подчёркивания по шаблону `inputtype_to_outputtype`. Метод `category()` группирует связанные обогатители в интерфейсе. Метод `key()` указывает, какое поле служит основным идентификатором — как правило, оно совпадает с входным типом.

### Реализация логики сканирования

Метод scan содержит основную логику сбора информации. Он получает список проверенных экземпляров `InputType` и возвращает список экземпляров `OutputType`.

```python
    async def scan(self, data: List[InputType]) -> List[OutputType]:
        """
        Resolve each domain to its IP address.

        Args:
            data: List of Domain objects to resolve

        Returns:
            List of Ip objects
        """
        results: List[OutputType] = []

        for domain in data:
            try:
                # Perform DNS resolution
                ip_address = socket.gethostbyname(domain.domain)
                # Create IP object
                ip = Ip(address=ip_address)
                results.append(ip)
                # Log successful resolution
                Logger.info(
                    self.sketch_id,
                    {"message": f"Resolved {domain.domain} to {ip_address}"}
                )
            except socket.gaierror as e:
                # DNS resolution failed
                Logger.info(
                    self.sketch_id,
                    {"message": f"Failed to resolve {domain.domain}: {e}"}
                )
                continue
            except Exception as e:
                # Unexpected error
                Logger.error(
                    self.sketch_id,
                    {"message": f"Error resolving {domain.domain}: {e}"}
                )
                continue
        return results
```

Эта реализация перебирает домены, выполняет DNS-разрешение, создаёт объект IP для успешных разрешений и логирует и успехи, и неудачи. Обработка ошибок гарантирует, что сбои не обрушат весь обогатитель, что важно при обработке многих доменов.

Входные данные уже проверены Pydantic до попадания в метод scan, поэтому можно быть уверенным, что все элементы — корректные объекты `Domain`.

### Реализация постобработки

Метод postprocess создаёт узлы и связи в графовой базе данных с помощью нового упрощённого API:

```python
    def postprocess(self, results: List[OutputType], input_data: List[InputType] = None) -> List[OutputType]:
        """
        Create graph nodes and relationships.

        Args:
            results: IP objects from scan phase
            input_data: Original Domain objects (preprocessed input)

        Returns:
            IP objects (unchanged)
        """
        # Create nodes and relationships
        for domain, ip in zip(input_data, results):
            # Create nodes by passing Pydantic objects directly
            self.create_node(domain)
            self.create_node(ip)

            # Create relationship by passing Pydantic objects directly
            self.create_relationship(domain, ip, "RESOLVES_TO")

            # Log the operation
            self.log_graph_message(
                f"IP found for domain {domain.domain} -> {ip.address}"
            )

        return results
```

Объекты Pydantic можно передавать напрямую в `create_node()` и `create_relationship()`. Эти методы автоматически определяют типы узлов, первичные ключи и значения свойств по моделям Pydantic.

Метод `create_node()` принимает объект Pydantic и автоматически создаёт узел Neo4j с правильной меткой и свойствами. Метод `create_relationship()` принимает два объекта Pydantic и строку типа связи, определяя всю необходимую информацию по самим объектам.

## Создание обогатителя с инструментами

Большинство обогатителей используют внешние инструменты для сбора данных. Создадим обогатитель, использующий инструмент Subfinder для перебора поддоменов.

### Импорт инструмента

Начните с импорта инструмента вместе с остальными зависимостями:

```python
from typing import List
from flowsint_core.core.enricher_base import Enricher
from flowsint_enrichers.registry import flowsint_enricher
from flowsint_core.core.logger import Logger
from flowsint_types import Domain
from tools.network.subfinder import SubfinderTool

@flowsint_enricher
class SubdomainEnricher(Enricher):
    """Enumerates subdomains for given domains using Subfinder."""

    # Define types as base types
    InputType = Domain
    OutputType = Domain

    @classmethod
    def name(cls) -> str:
        return "domain_to_subdomains"

    @classmethod
    def category(cls) -> str:
        return "Domain"

    @classmethod
    def key(cls) -> str:
        return "domain"

# Export types
InputType = SubdomainEnricher.InputType
OutputType = SubdomainEnricher.OutputType
```

### Использование инструмента в scan

Метод scan создаёт экземпляр инструмента и использует его:

```python
    async def scan(self, data: List[InputType]) -> List[OutputType]:
        """
        Find subdomains using Subfinder tool.
        Args:
            data: List of Domain objects
        Returns:
            List of discovered subdomain Domain objects
        """
        results: List[OutputType] = []
        # Instantiate the tool
        subfinder = SubfinderTool()

        for domain in data:
            Logger.info(
                self.sketch_id,
                {"message": f"Enumerating subdomains for {domain.domain}"}
            )
            try:
                # Launch the tool
                subdomains = subfinder.launch(domain.domain)
                # Convert strings to Domain objects
                for subdomain in subdomains:
                    results.append(Domain(domain=subdomain, root=False))
                Logger.info(
                    self.sketch_id,
                    {"message": f"Found {len(subdomains)} subdomains for {domain.domain}"}
                )
            except Exception as e:
                Logger.error(
                    self.sketch_id,
                    {"message": f"Error enumerating subdomains for {domain.domain}: {e}"}
                )
                continue
        return results
```

Обратите внимание: инструмент возвращает сырые строки, а обогатитель преобразует их в полноценные объекты Domain. Такое разделение ответственности делает инструменты простыми, а преобразование типов остаётся за обогатителями.

### Создание узлов и связей графа

Фаза postprocess создаёт связи «родитель — потомок» между доменами и поддоменами:

```python
    def postprocess(self, results: List[OutputType], input_data: List[InputType]) -> List[OutputType]:
        """
        Create graph nodes and relationships for domains and subdomains.

        Args:
            results: Discovered subdomain Domain objects
            input_data: Original parent Domain objects

        Returns:
            Subdomain Domain objects
        """
        # Create nodes for parent domains
        for domain in input_data:
            self.create_node(domain)

        # Create nodes for subdomains and relationships
        for subdomain in results:
            self.create_node(subdomain)

            # Extract parent domain name and create relationship
            parent_domain_name = self._extract_parent_domain(subdomain.domain)
            parent_domain = Domain(domain=parent_domain_name)

            # Create relationship using Pydantic objects
            self.create_relationship(parent_domain, subdomain, "HAS_SUBDOMAIN")

            # Log the operation
            self.log_graph_message(
                f"Subdomain found: {parent_domain_name} -> {subdomain.domain}"
            )

        return results

    def _extract_parent_domain(self, subdomain: str) -> str:
        """Extract parent domain from subdomain."""
        parts = subdomain.split('.')
        if len(parts) >= 2:
            return '.'.join(parts[-2:])
        return subdomain
```

## Добавление параметров в обогатители

Многим обогатителям нужны настраиваемые пользователем параметры. Создадим обогатитель, который сканирует порты с настраиваемыми опциями.

### Определение схемы параметров

Метод класса `get_params_schema()` определяет, какие параметры принимает ваш обогатитель:

```python
from typing import List, Dict, Any, Optional
from flowsint_enrichers.registry import flowsint_enricher
from flowsint_core.core.enricher_base import Enricher
from flowsint_types import Ip, Port
from tools.network.naabu import NaabuTool

@flowsint_enricher
class IpToPortsEnricher(Enricher):
    """Scans IP addresses for open ports."""

    # Define types as base types
    InputType = Ip
    OutputType = Port

    @classmethod
    def name(cls) -> str:
        return "ip_to_ports"

    @classmethod
    def category(cls) -> str:
        return "IP"

    @classmethod
    def key(cls) -> str:
        return "address"

    @classmethod
    def get_params_schema(cls) -> List[Dict[str, Any]]:
        """Define configurable parameters for this enricher."""
        return [
            {
                "name": "mode",
                "type": "select",
                "description": "Scan mode: active scanning or passive enumeration",
                "required": True,
                "default": "passive",
                "options": [
                    {"label": "Passive", "value": "passive"},
                    {"label": "Active", "value": "active"},
                ],
            },
            {
                "name": "port_range",
                "type": "string",
                "description": "Port range to scan (e.g., '1-1000' or '80,443,8080')",
                "required": False,
            },
            {
                "name": "top_ports",
                "type": "select",
                "description": "Scan only the most common ports",
                "required": False,
                "options": [
                    {"label": "Top 100", "value": "100"},
                    {"label": "Top 1000", "value": "1000"},
                ],
            },
            {
                "name": "PDCP_API_KEY",
                "type": "vaultSecret",
                "description": "ProjectDiscovery Cloud Platform API key for passive mode",
                "required": False,
            },
        ]

# Export types
InputType = IpToPortsEnricher.InputType
OutputType = IpToPortsEnricher.OutputType
```

Схема параметров определяет тип, описание, обязательность, значения по умолчанию, а для параметров-списков — доступные варианты. Тип `vaultSecret` интегрируется с зашифрованным хранилищем учётных данных Flowsint.

### Использование параметров в обогатителе

Параметры доступны через `self.params` в методе scan:

```python
    async def scan(self, data: List[InputType]) -> List[OutputType]:
        """
        Scan IPs for open ports using configured parameters.
        Args:
            data: List of Ip objects to scan
        Returns:
            List of Port objects
        """
        results: List[OutputType] = []
        # Extract parameters
        mode = self.params.get("mode", "passive")
        port_range = self.params.get("port_range")
        top_ports = self.params.get("top_ports")
        api_key = self.get_secret("PDCP_API_KEY")

        # Instantiate tool
        naabu = NaabuTool()

        for ip in data:
            Logger.info(
                self.sketch_id,
                {"message": f"Scanning {ip.address} in {mode} mode"}
            )
            try:
                # Launch tool with parameters
                scan_results = naabu.launch(
                    target=ip.address,
                    mode=mode,
                    port_range=port_range,
                    top_ports=top_ports,
                    api_key=api_key
                )
                # Convert tool results to Port objects
                for result in scan_results:
                    port = Port(
                        number=result.get("port"),
                        protocol=result.get("protocol", "tcp").upper(),
                        state="open",
                        service=result.get("service"),
                        banner=result.get("version")
                    )
                    results.append(port)
            except Exception as e:
                Logger.error(
                    self.sketch_id,
                    {"message": f"Error scanning {ip.address}: {e}"}
                )
                continue
        return results
```

## Несколько типов результата

Некоторые обогатители выдают результаты нескольких типов. Можно определить собственный возвращаемый тип с помощью Pydantic:

```python
from pydantic import BaseModel
from flowsint_enrichers.registry import flowsint_enricher
from flowsint_core.core.enricher_base import Enricher
from typing import List
from flowsint_types import Website, Email, Phone

class CrawlerResults(BaseModel):
    """Results from web crawler including multiple entity types."""
    website: Website
    emails: List[Email] = []
    phones: List[Phone] = []

@flowsint_enricher
class WebsiteToCrawlerEnricher(Enricher):
    """Crawls websites to extract emails and phone numbers."""

    # Define types as base types
    InputType = Website
    OutputType = CrawlerResults

    async def scan(self, data: List[InputType]) -> List[OutputType]:
        """Crawl websites and extract contact information."""
        from tools.network.reconcrawl import ReconCrawlTool

        results: List[OutputType] = []
        crawler_tool = ReconCrawlTool()

        for website in data:
            try:
                # Launch crawler
                crawl_data = crawler_tool.launch(website.url)

                # Extract entities
                emails = [Email(email=e) for e in crawl_data.get("emails", [])]
                phones = [Phone(number=p) for p in crawl_data.get("phones", [])]

                # Create result object
                result = CrawlerResults(
                    website=website,
                    emails=emails,
                    phones=phones
                )
                results.append(result)

            except Exception as e:
                Logger.error(self.sketch_id, {"message": f"Crawl error: {e}"})

        return results

    def postprocess(self, results: List[OutputType], input_data: List[InputType]) -> List[OutputType]:
        """Create nodes for all discovered entities."""
        for result in results:
            # Create website node using Pydantic object
            self.create_node(result.website)

            # Create email nodes and relationships
            for email in result.emails:
                self.create_node(email)
                self.create_relationship(result.website, email, "HAS_EMAIL")

            # Create phone nodes and relationships
            for phone in result.phones:
                self.create_node(phone)
                self.create_relationship(result.website, phone, "HAS_PHONE")

            self.log_graph_message(
                f"Processed {len(result.emails)} emails and {len(result.phones)} phones from {result.website.url}"
            )

        return results

# Export types
InputType = WebsiteToCrawlerEnricher.InputType
OutputType = WebsiteToCrawlerEnricher.OutputType
```

## Регистрация обогатителя

Регистрировать обогатитель где-либо не нужно: достаточно добавить к классу декоратор `@flowsint_enricher`, и автоматическое обнаружение подхватит его.

```python
from flowsint_enrichers.registry import flowsint_enricher
from flowsint_core.core.enricher_base import Enricher

@flowsint_enricher
class MyEnricher(Enricher):
...
```

## Тестирование обогатителя

Тесты помогают убедиться, что обогатитель работает правильно, и упрощают отладку. Создайте тестовый файл в `flowsint-enrichers/tests/`:

```python
# tests/test_domain_to_ip.py
import pytest
from flowsint_enrichers.domain.to_ip import DomainToIpEnricher
from flowsint_types import Domain, Ip

@pytest.mark.asyncio
async def test_enricher_metadata():
    """Test enricher metadata is correctly defined."""
    assert DomainToIpEnricher.name() == "domain_to_ip"
    assert DomainToIpEnricher.category() == "Domain"
    assert DomainToIpEnricher.key() == "domain"

@pytest.mark.asyncio
async def test_type_definitions():
    """Test InputType and OutputType are correctly defined."""
    assert DomainToIpEnricher.InputType == Domain
    assert DomainToIpEnricher.OutputType == Ip

@pytest.mark.asyncio
async def test_scan():
    """Test DNS resolution works."""
    enricher = DomainToIpEnricher(sketch_id="test", scan_id="test")
    input_data = [Domain(domain="example.com")]
    results = await enricher.scan(input_data)

    assert len(results) > 0
    assert isinstance(results[0], Ip)
    assert results[0].address  # Should have an IP address
```

Эти тесты проверяют корректность метаданных обогатителя, правильность определений типов и то, что логика сканирования даёт ожидаемые результаты. Проверку входных данных автоматически выполняет Pydantic, поэтому предобработку отдельно тестировать не нужно.

## Лучшие практики

При создании обогатителей тщательно продумывайте обработку ошибок. Сбор информации затрагивает множество внешних систем, которые могут отказать непредсказуемым образом. Обогатитель должен корректно обрабатывать ошибки, чётко логировать сбои и продолжать обработку оставшихся элементов, а не падать целиком.

Всегда используйте утилиту Logger для отслеживания хода работы и ошибок. Логгер интегрируется с системой мониторинга Flowsint и помогает пользователям понимать, что происходит во время долгих обогатителей. Успешные операции логируйте на уровне info, а ошибки — на уровне error.

Определяйте InputType и OutputType как базовые типы (например, `Domain`, а не `List[Domain]`). Базовый класс сам выполняет оборачивание в список и валидацию. Так определения типов получаются чище и понятнее.

Всегда экспортируйте типы в конце файла так:
```python
InputType = YourEnricher.InputType
OutputType = YourEnricher.OutputType
```

Используйте упрощённый API графа: передавайте объекты Pydantic напрямую в `create_node()` и `create_relationship()`. Это устраняет шаблонный код и снижает число ошибок. Методы сами определяют типы узлов, первичные ключи и свойства по моделям Pydantic.

Разделяйте ответственность между двумя фазами. Сканирование должно заниматься сбором и обработкой данных. Постобработка должна создавать структуры графа. Проверка входных данных выполняется автоматически через Pydantic, поэтому вручную заниматься ею не нужно.

Используйте подсказки типов везде. Они обеспечивают автоматическую валидацию, лучшую поддержку в IDE и служат встроенной документацией. Атрибуты класса InputType и OutputType всегда должны быть типами Pydantic из пакета flowsint-types.

При работе с инструментами помните, что они возвращают сырые структуры данных. За преобразование вывода инструмента в корректные типы Flowsint отвечает обогатитель. Обычно это преобразование выполняется на фазе scan.

Подробно документируйте обогатитель. Docstring класса, метод documentation и описания параметров отображаются в интерфейсе. Понятная документация помогает пользователям понять, что делает ваш обогатитель и как его настроить.

### Работа с ограничениями частоты запросов API

При работе с API, у которых есть ограничения на частоту запросов, добавляйте задержки между запросами:

```python
    async def scan(self, data: InputType) -> OutputType:
        """Scan with rate limiting to respect API limits."""
        import asyncio
        results = []
        delay_seconds = 1  # Delay between requests
        for item in data:
            result = await self._query_api(item)
            if result:
                results.append(result)
            # Respect rate limits
            await asyncio.sleep(delay_seconds)
        return results
```

### Запасные источники данных

Реализуйте запасную логику на случай, если основные источники недоступны:

```python
    async def scan(self, data: InputType) -> OutputType:
        """Try multiple data sources with fallback logic."""
        results = []

        for domain in data:
            # Try primary source
            result = self._query_primary_source(domain)

            if not result:
                # Fall back to secondary source
                Logger.info(
                    self.sketch_id,
                    {"message": f"Primary source failed for {domain}, trying fallback"}
                )
                result = self._query_fallback_source(domain)

            if result:
                results.append(result)

        return results
```

## Устранение неполадок

Если ваш обогатитель не появляется в API, убедитесь, что вы применили к классу декоратор `@flowsint_enricher`, что файл лежит в `flowsint-enrichers/src/flowsint_enrichers/` и что вы перезапустили API-сервер. Автообнаружение через `load_all_enrichers()` выполняется при запуске, поэтому после добавления файлов нужен перезапуск.

При ошибках импорта убедитесь, что все зависимости установлены, а в файле обогатителя нет синтаксических ошибок. Проверьте, что вы импортируете из правильных пакетов.

Если метод scan не находит результатов, добавьте логирование, чтобы понять, что происходит. Проверьте, что инструменты установлены и доступны, API-ключи действительны (если они нужны) и входные данные имеют ожидаемый формат.

Если связи в графе не появляются, проверьте, что в методе postprocess вы создаёте и узлы, и связи. Убедитесь, что имя типа связи указано верно и в `create_relationship()` передаются правильные объекты узлов.

## Дальнейшие шаги

Когда вы создали и зарегистрировали обогатитель, он становится доступным через API для запуска пользователями. Обогатители можно объединять в потоки (Flows), где результат одного обогатителя подаётся на вход другого. Это позволяет строить сложные последовательности сбора информации.

Помните, что обогатители — это сердце возможностей Flowsint по сбору информации. Хорошо спроектированные обогатители, которые корректно обрабатывают ошибки, чётко логируют ход работы и создают осмысленные связи в графе, делают всю платформу мощнее и удобнее.

Если вы создали новые обогатители, которые, по вашему мнению, могут помочь сообществу, будем очень признательны, если вы сделаете их открытыми. Помогайте сообществу так же, как оно помогает вам!
